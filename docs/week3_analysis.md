# Week 3：用 Parnia 的缓存数据做误差分析和第一次小训练（2026-11-14）

数据：Parnia 的 `cache/`，28 段（train 20 / val 4 / test 4），每段 8 s、30 fps，`<clip>_s2c.npz`（原始 S2C，未平滑）+ `<clip>_gt.npz`（PianoMotion10M 标注）。格式和 `refiner/motion_format.py` 一致。

复现：

```bash
python tools/analyze_cache.py cache/                                  # 误差分析
python tools/week3_experiment.py cache/ --steps 1000 --seeds 0 1 2    # 小训练（CPU，约 10 分钟）
```

## 1. 观察到的问题（28 段，左右手平均）

| 指标 | 原始 S2C | 平滑后 | 真值 |
|---|---|---|---|
| 手指角度误差 (°) | 10.6 | 10.5 | – |
| 手掌整体朝向误差 (°) | **17.0** | 16.9 | – |
| 手腕 x / y / z 误差 (mm) | 40 / 16 / **624** | 40 / 16 / 623 | – |
| 图像平面手腕误差 (px, 1920×1080) | 91 | 91 | – |
| 95% 手指速度 (°/s) | 151 | 139 | 185 |
| 手指角加速度 (°/s²) | 821 | 692 | 1057 |

1. **深度 z 基本不可信。** S2C 的相机焦距是 37500 px，手离相机 12～27 m（见 S2C `datasets/show.py`），所以深度几乎看不出来。真值的 z 在一段里标准差也有 0.6 m，相邻帧能跳 5～14 cm。手腕误差 98% 来自 z，x/y 只有几厘米。
2. **手掌整体朝向是最大的旋转误差（17°）**，比手指（10.6°）还大。但 Week 2 版 refiner 完全不改这一项。
3. **S2C 不是太抖，而是太平。** 真值比 S2C 更抖（标注噪声），S2C 的快速手指动作比真值少（151 vs 185 °/s）。再平滑只会把触键抹得更平，平滑基本不降低误差。
4. 有两段的左手完全没有标注（`valid_left` 全 0），已在指标和损失里跳过。

## 2. 改动（v2，都是可选项，默认值不变）

- `RefinerConfig(refine_global=True)`：refiner 也修正手掌整体朝向，R = R_raw · exp(Δ)，同样零初始化、有上限。
- `LossWeights(rec_glob=1.0)`：加整体朝向的重建损失。
- `LossWeights(trans_axis=(1, 1, 0.25))`：降低深度 z 的权重。
- `LossWeights(smooth_target=True)`：速度损失对比的是 Savitzky-Golay 平滑后的真值，不学标注噪声。
- 3D 网页查看器改成弱透视：x/y 按 z̄/z 缩放，深度固定，并自动判断左右。

## 3. 结果（验证集 4 段，3 个随机种子平均，1000 步）

| | 手指 ° | 朝向 ° | 手腕 xy mm | 图像 px | 95% 手指速度 |
|---|---|---|---|---|---|
| 原始 S2C | 8.62 | 12.80 | 27.0 | 52.1 | 169 |
| 平滑 | 8.59 | 12.74 | 27.0 | 52.1 | 156 |
| v1（Week 2） | 9.05 | 12.80 | 29.1 | 55.6 | 143 |
| v2（Week 3） | 9.27 | 14.08 | 30.6 | 58.9 | 146 |

训练集上（seed 0）两版都大幅变好：手指 10.9° → 6.9°，图像误差 85 → 42 px。v2 的朝向误差 17.2° → 10.5°，v1 不变。**但验证集上两版都比原始 S2C 差。** 这是典型的过拟合：20 段 × 8 s 只有 4800 帧，网络有约 40 万参数，把训练片段记住了。

按计划的规则：变差时保留原始 S2C 开关，先查原因。所以 `refine_global` 先不设成默认。

## 4. 下一步

1. **数据（最重要，Parnia）**：PianoMotion10M 有上千段，缓存至少几百段再训练（同一个视频的片段只放进同一个划分）。
2. **正则（yumin）**：在验证集上做早停；更小的 hidden（64）；更大的 `res_*` 权重或更小的 `max_rot`。数据多了以后，再比较 v1 和 v2。
3. 验证集只有 4 段，差 1° 以内基本是噪声。之后用 test 4 段只报最终结果。
